# Codex 보충 요청 (같은 세션, 2026-11-15)

방금 쓴 `docs/world/architecture_design.md`를 아래 기준으로 고친다. 앞 요청의 "갈리는 지점 = 보상 전에 본 것을 나중에 쓰기"는 사용자의 요구보다 좁게 잡은 것이었다 (Claude의 정리 실수). 그것은 아래 원인 중 하나의 부산물로 내린다.

## 사용자의 실제 질문

TD(λ) 빠른 기억 (에피소드 안에서 매 스텝 쓰는 선형 가치 기억, tdpc)이 forage에서 그렇게 좋은 보상 기억과 실시간 적응을 보인다면, **마인크래프트 수준의 자율 에이전트 연구에서는 왜 쓰이지 않는가 (확장 불가능성)**, 그리고 그것을 해결하는 것이 목표다.
(TD(λ) 자체는 DreamerV3의 critic처럼 1억 스텝에 걸친 느린 가중치 학습에는 쓰인다. 쓰이지 않는 것은 에피소드 안 빠른 기억으로서다.)
## Claude가 정리한 출발점 (검토·수정 대상, 그대로 믿지 말 것)

forage에서 TD(λ) 빠른 기억이 된 전제 넷, 마인크래프트에서는 넷 다 깨진다:

| 전제 | forage | 마인크래프트 |
|---|---|---|
| 1. 같은 상황이 에피소드 안에서 반복된다 | 상황 약 196개, 보상 뒤 출발로 돌아가 같은 길을 수십 번 | 같은 시야의 재방문이 드묾 |
| 2. 같은 보상이 반복된다 | 보상 칸 하나를 계속 | 성취 12개는 에피소드당 한 번씩. 반복은 체력·허기뿐 |
| 3. 보상까지 짧다 | 최단 약 4스텝, 흔적 창이 덮음 | 수천 스텝. 전파에 같은 경로의 반복 경험 필요 |
| 4. 상황마다 특징이 겹치지 않는다 | 시야가 위치마다 유일 → 사실상 one-hot | 안 겹치게 하면 일반화가 없고, 겹치면 간섭 |

구조적 원인 둘:
- **TD는 지금 목표에 대한 가치를 캐시한다.** 재방문이 있어야 쓸모 있고 (1, 3), 목표가 유지돼야 맞다 (2). 목표·보상이 바뀌면 캐시가 틀리고, 고칠 수단은 음의 δ로 천천히 덮어쓰기뿐이다.
- **쓰기를 고르지 않는다.** δ ≠ 0이면 매 스텝 고정 크기 w에 쓰므로 간섭이 사건이 아니라 스텝 수로 늘어난다.

뒤집은 요구: 가치 대신 세계의 사실 (무엇이 어디 있고 무엇을 하면 무엇이 되는가)을 기억하고 가치는 읽을 때 지금의 목표로 계산한다 (자유에너지원리: 기억 = 생성 모델의 빠른 파라미터, 가치 = 추론). 중요한 것만 골라 쓰고 증거로만 버린다 (BTSP의 사건이 일으키는 한 번 쓰기). 전제 4 (표현의 일반화·간섭)는 느린 가중치의 몫이다.

## 고칠 것

1. **문제 정의**를 "TD(λ) 빠른 기억의 확장 불가능성"을 중심으로 다시 쓴다. 위 전제·원인이 맞는지, 빠졌거나 틀린 것이 있는지 판단하고 고친다. 각 전제가 깨질 때 TD(λ) 빠른 기억이 무엇 때문에 얼마나 나빠지는지 가능한 한 정량적인 형태로.
2. **아키텍처**는 첫 판에서 유효한 것을 남기고, 위 원인 각각을 어느 구성 요소가 해결하는지 대응표로 보인다. 해결하지 못하는 원인이 있으면 그렇다고 쓴다.
3. **첫 입증 과제**는 forage에서 전제를 하나씩 깨는 손잡이로 잡는다 (예: 보상 한 번씩, 목표가 차례로 바뀜, 반복 무늬의 큰 격자 = 겹침, 긴 거리). tdpc (TD(λ) 빠른 기억)가 각 손잡이에서 어떻게 무너질지와 제안 구조가 어떻게 버틸지 사전 예측과 실패 기준을 붙인다. 손잡이 하나만 먼저 한다면 어느 것인지 권고한다.
4. 첫 판의 "보상 전에 본 것을 나중에 쓰기"는 원인 (가치 캐시) 의 부산물로 위치를 바꿔 남긴다.

작업 규칙은 앞 요청과 같다 (구현·긴 학습 없음, 다른 파일 수정 없음, 문서 하나, 끝나면 커밋, 푸시 안 함, 마지막 응답에 요약).
