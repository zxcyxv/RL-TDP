# Codex 연구 요청: 근본적으로 더 나은 아키텍처 (2026-11-17)

## 요청

이 레포 (`/workspace/RL-TDP`, 브랜치 `claude/busy-goldberg-392gtg`)의 목표에 대해, **근본적으로 더 나은 아키텍처가 되려면 무엇이 어떻게 바뀌어야 하는지** 연구해 달라. 기존 구조를 부분적으로 고치는 처방이든, 다른 구조든 좋다. 결론은 당신이 레포와 문헌을 직접 검토해서 내린다.

**기존 레포의 맥락을 존중한다.** 지금까지의 목표, 원리, 사용자 결정, 실험 기록에는 이유가 있다. 그것을 바꾸자고 할 때는 무엇을, 왜 바꾸는지 기록과 근거를 들어 밝힌다. 기록과 해석이 다르면 결과 파일과 실행 코드를 우선한다.

## 바라는 결과

1. 목표와 요구 (HANDOVER 0절, ROADMAP)에 비추어, 지금 아키텍처의 근본 한계가 무엇인지. 근거는 기록, 코드, 수식, 문헌.
2. 근본적으로 더 나은 아키텍처의 제안. 구성 요소, 식, 느린 학습과 세션 안 빠른 갱신의 분업, 학습 목적.
3. 레포의 기존 원리와 결정 가운데 유지하는 것, 바꾸는 것, 그 이유.
4. 이 제안이 맞는지 가를 수 있는 시험. 무엇을 바꾸고 무엇을 고정하는지, 사전 예측과 반증 기준.
5. 확실하지 않은 것과 가정한 것의 구분. 문헌은 확인한 것과 기억에 의존한 것을 구분해 적는다.

## 중간 답변

## 규칙 (사용자)

- 이론과 설계만 한다. 코드 구현, 학습, 실험 실행은 하지 않는다 (구현과 실험은 Claude가 맡는다). 코드와 결과 파일은 읽어도 된다.
