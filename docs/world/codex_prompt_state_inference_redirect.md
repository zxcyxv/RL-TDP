# 방향 전환 (사용자 개입, 같은 요청의 연속)

지금까지 읽은 것과 판단은 그대로 쓰되, 다음 제약을 추가한다. 이 제약이 앞 요청의 어떤 항목보다 우선한다.

- **상태의 분해를 손으로 정하지 않는다.** "문 정체성을 유지하는 숨은 상태"와 "현재 장면 상태"를 설계자가 나눠 두는 것은 과제 구조를 정답으로 넣는 편향이다. Minecraft에서는 무엇을 상태 변수로 나눌지 아무도 알려 주지 않는다. 보편적으로 확장되지 않는 설계는 받지 않는다.
- **상태 구조는 느린 학습으로 얻는다.**
  - 이산판: CSCG처럼 같은 관측에 숨은 상태 복제본을 두고 전이를 데이터로 배우면, "왼쪽 문 뒤 복도"와 "오른쪽 문 뒤 복도"가 다른 복제본으로 갈라지는 식. 문 정체성은 학습된 전이 구조에서 생겨나야 한다.
  - 연속판 (Craftax·RSSM): 같은 구별을 학습된 잠재가 얻는다. 두 판의 대응을 밝힌다.
- **학습 신호의 성격을 밝힌다**: 상태 구조 (복제본 배정·전이)를 배우는 신호가 국소적인지, 즉 경사나 통계가 대기 D를 건너야 하는지. 건너야 한다면 학습 길이 밖 일반화가 어떻게 되는지.
- 빠른 쓰기 (관측 모형의 세계별 Hebb·디리클레 누적, 키 = 추론된 상태 믿음), 새로움·정밀도가 계수에서 나오는 것, 흔적의 자리, "남은 문" 반례, 구현 명세·사전 예측은 이 제약 아래에서 다시 쓴다.
- 산출물·작업 규칙은 같다 (`docs/world/state_inference_design.md` 한 파일, 그 파일만 커밋, 마지막 응답에 요약).
