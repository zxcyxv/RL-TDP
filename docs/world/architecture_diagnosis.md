# 아키텍처 진단 — 2026-11-15, Codex

**권고는 하나다. 산출물 사실을 ‘시작할 때 보존한 원인 주소 → 도착한 내용’으로 쓰는 작은 KV 시냅스로 단순화한다.** 주소 귀속을 먼저 확인한다. 그다음 고정 가소성의 정밀도 가중 delta 쓰기를 쓴다. 칸별 공분산과 Beta 증거 망각은 보류한다.

현재 결과는 기억 용량 부족을 입증하지 않는다. 평가 시점, 주소의 문맥 변화, 지연 귀속, 정적 RLS의 갱신이 섞여 있다. 더 큰 모델이나 더 정교한 변화 필터부터 넣을 근거가 없다.

이번 작업은 코드·JSON 검토와 세션 길이 산술만 했다. 구현·학습·새 성능 실험은 하지 않았다. `docs/world/README.md`는 읽지 않았다. 코드의 설명 주석도 인과 증거로 쓰지 않았다.

## 2. 무엇이 실패했는가

### 2.1 구현·평가·척도: 확인된 것

| 항목 | 확인된 동작 | 판단 |
|---|---|---|
| 평가 시점 | EL 62–70은 재방문 종료 뒤에도 최장 세션까지 WAIT를 붙인다. EP 168–169는 이 구간도 기억에 쓴다. | **나열된 교사 경로 밖의 추가 쓰기가 있다. 평가 시점부터 고정한다.** |
| 도착 정렬 | ER의 `due=t+8`, 다음 시각 `t+1`과 EL의 판정 인덱스 `j+7`은 맞는다. | 도착 오프바이원 버그는 찾지 못했다. |
| 잔차 읽기 | 쓰기는 `y−μ⁰`, 점수는 `Mz`다. `μ⁰+Mz`가 아니다. EP 74, 177–182. | 명시된 잔차 probe에는 맞는다. 전체 도착 예측 정확도라고 해석하면 불일치다. |
| 정밀도 의미 | `s²=v/vmax`는 회귀 입력을 키운다. 실제 관측 잡음은 모든 칸에서 `R=0.01`이다. EP 73–90. | RLS는 `S=R+zᵀPz`로 오차를 가중한다. 그러나 WM의 `1/v`로 관측 오차를 가중하는 구현은 아니다. |
| 키의 척도 | 키 정규화가 없고 `P₀=I`, R은 고정이다. | 키 크기를 바꾸면 초기 출력 불확실성·gain·NLL도 바뀐다. 주소 방향만 학습하는 비교가 아니다. |
| 변경 분산 | EP의 변경 가설은 `N(r;0,R+v_p)`다. `v_p`는 모든 스텝의 다음 칸 예측으로 학습한다. | 도착 조건부 산출물 분산, 관측 잡음, 변경 크기는 서로 다른 양이다. 현재는 분리하지 않았다. |
| 공분산 증가 | EP 86의 증가는 `zᵀΔPz=χv_p`다. | 이 식의 정규화는 대수적으로 맞다. 분모가 하나 더 들어간 버그가 아니다. |
| 학습 꼬리 | `range(0,T−L+1,L)`은 마지막 `T%64`를 버린다. | 학습 세계에서는 T=516, 꼬리 4스텝이다. C 도착 누락은 512세계 중 1개다. 주원인으로 보지 않는다. |
| 동점 | b0는 항상 앞선 B 인덱스다. `argmax`는 첫 동점을 택한다. | 정확 동점은 b0에 유리하다. 발생 빈도는 미측정이다. |

패딩 크기는 사소하지 않다. seed 1000–1255의 교사 행동열만 생성해 계산했다. 환경 rollout은 하지 않았다.

| 수량 | 최소 | 중앙값 | 최대 |
|---|---:|---:|---:|
| 원래 교사 길이 | 418 | 444 | 510 |
| 추가 padding WAIT | 0 | 66 | 92 |
| C 도착 쓰기 뒤 원래 교사 끝까지 추가 쓰기 | 2 | 2 | 7 |

즉 ‘패딩만 제거’해도 C 직후와 같지는 않다. 요청의 ‘그 시점’을 C 직후로 볼지, 귀환까지 끝난 재방문 종료로 볼지는 구분해야 한다. 즉시 수정을 보려면 C 관측을 쓴 직후를 복제한다. 원래 경로 평가와도 함께 비교한다. 추가 blank 쓰기가 실제 순위를 얼마나 바꿨는지는 아직 모른다.

### 2.2 구조: 동작은 확인, 주원인 여부는 가설

| 실패 후보 | 코드·측정에서 확인된 사실 | 아직 확인되지 않은 인과 해석 |
|---|---|---|
| 현재 관측만 쓰는 WM | WM 입력은 현재 장면과 행동뿐이다. pending·나이는 없다. EP 39–42. 같은 빈 HUD와 대기 행동에서도 다음 도착 여부는 다를 수 있다. | WM만으로 지연 시각을 식별할 수 없다. 이 모호함이 분산에 섞이고 시간 예측의 부담이 빠른 흔적으로 간다. 전체 에이전트가 해결 불가능하다는 뜻은 아니다. |
| 지연 귀속 혼합 | 모든 스텝의 키를 `e←αe+k`에 넣는다. 도착 때도 이동·대기 흔적에 산출물을 쓴다. EP 71–91. | 원인 상호작용보다 귀환 경로가 강한 주소가 되었을 수 있다. 방향·코사인을 재야 확정된다. |
| 사실 주소의 의뢰 의존 | 키 입력에 시야 9칸과 HUD 3칸이 모두 들어간다. b1 관찰 때 카드는 BLANK, 최종 읽기는 CARD_BACK이다. b0는 의뢰 중 B 재경험이 있다. | b1이 지워진 것이 아니라 다른 주소로 읽힐 수 있다. b0 편향을 변경 감지 실패만으로 설명할 수 없다. |
| 빈칸의 반복 쓰기 | 대부분의 스텝에서 산출물 HUD는 빈칸이다. 같은 M에 계속 회귀한다. | 원인 주소가 섞이면 산출물 내용까지 blank 쪽으로 당길 수 있다. 보존·패딩 ablation이 필요하다. |
| 정적 회귀의 평균화 | 망각 없는 RLS는 세션의 모든 `(z,r)`를 같은 고정 가중치의 관측으로 누적한다. P에는 시간 회복이 없다. | 동일 주소를 재사용할수록 새 C의 gain이 작아질 수 있다. 실제 gain 로그는 없다. |
| 학습 목적의 우회 | 키 손실은 모든 스텝의 다음 관측 NLL이다. 최종 b1 회상·변경 판정은 직접 최적화하지 않는다. | 빈번한 이동 예측이나 불확실성 조절에 좋은 키가 사실 보존에는 나쁠 수 있다. |
| 긴 간격의 경사 단절 | 64스텝마다 carry를 `stop_gradient`한다. 조각마다 키 가중치도 바뀐다. EP 138–154. | 256스텝 뒤 손실이 최초 쓰기 주소까지 전달되지 않는다. 다만 반복된 짧은 학습으로 좋은 규칙을 배울 가능성까지 막는 것은 아니다. |

칸별 NLL은 `0.5·(E/S+H·log S)`다. 주어진 제곱오차 E에서 최적 S는 `E/H`다. 따라서 키는 평균 예측뿐 아니라 불확실성도 조절한다. 큰 이동 키가 이 역할을 맡았을 가능성은 있다. log S 벌점도 있으므로 무제한 분산 부풀리기라고 단정하지 않는다.

8스텝 지연 자체는 64스텝 BPTT보다 짧다. 따라서 ‘BPTT가 짧아 도착을 전혀 연결할 수 없다’는 진단은 틀리다. 경계에 걸리는 사례와 장기 보존 학습은 별개 문제다.

도착 읽기에서 시작 키의 직접 계수는 `α⁷≈0.545`다. 위 한 세계의 평균 크기를 대입하면 약 0.12다. 그동안 여러 이동 키가 더해진다. 이는 혼합 가설의 근거다. 벡터 방향을 모르므로 기여율로 해석하지 않는다. 또 `α²⁵⁶=2⁻³²`다. 장기 기억은 e가 아니라 M에 있어야 한다. 흔적 소멸 자체를 장기 기억 실패로 부르지 않는다.

정적 RLS는 정확히 같은 주소라면 과거·현재 내용을 평균한다. b0는 이전 B 관측 두 번, 변경 C 관측 한 번이다. 최신 사실을 원하는 과제와 목적이 다르다. 다만 이상적인 분리 주소에서 b1의 순수 B가 이 혼합보다 높은 점수를 얻을 수도 있다. **평균화만으로 현재 46%를 설명했다고 주장하지 않는다.**

### 2.3 증거 망각이 해결하지 못한 이유

| 구분 | 확인 | 판단·예측 |
|---|---|---|
| 첫 판의 척도 | 변경 분산이 `R+‖z‖²`였다. 스칼라 판은 96차원 우도를 한꺼번에 비교한다. 사용자 측정에서 모든 도착 χ=0이다. | 큰 분산은 log-determinant 벌점을 받는다. 흔적 크기를 내용 변화 크기로 쓰면 지나치게 넓은 대안을 만들 수 있다. 검출 실패를 ‘변경 증거 없음’으로 읽으면 안 된다. |
| 주소 | P 증가는 지금의 누적 흔적 z 방향이다. | χ가 맞아도 원인 주소가 틀리면 잘못된 연결을 수정한다. 검출기만 개선해도 해결되지 않는다. |
| 위험률의 표본 | Beta는 주소별이 아니라 칸별이다. 매 스텝 갱신한다. EP 83–87. | blank·새 주소·미학습 오차도 섞인다. ‘확인한 사실이 바뀔 확률’로 해석하기 어렵다. 실제 h·χ 분포는 필요하다. |
| 학습·평가 차이 | 키 학습의 `write_scan`에는 `evidence=True`가 없다. EP 144. | 망각을 켠 기억 동역학으로 키를 학습하지 않았다. 열화의 한 후보이며, 이것만이 원인이라는 증거는 없다. |
| 근사 방식 | 변경 우도는 평균 0의 새 내용이다. 실제 갱신은 옛 M을 두고 P만 늘린다. | 정확한 변경/유지 혼합 posterior는 아니다. 적응 필터의 휴리스틱이다. 정밀한 필터로 확장할 우선순위는 낮다. |

칸별 정밀도 판의 `other=0`은 B 관련 정보가 어느 정도 남았다는 증거다. 망각 뒤 `other≈15–16%`는 유용한 구분까지 흐려졌다는 신호다. 어느 시점의 어느 주소가 손상됐는지는 집계율만으로 특정할 수 없다.

### 2.4 이 결과가 아직 말하지 않는 것

| 주장 | 판정 |
|---|---|
| 처음 본 세계에서 순전파 쓰기가 작동하는가 | 코드상 그렇다. 시험 세션 중 역전파는 없다. 기억 상태 크기·스텝당 연산도 고정이다. |
| 느린 가중치에 세계별 배정·가치가 새었는가 | 입증되지 않았다. 학습/시험 세계 시드는 분리된다. 느린 손실에 보상도 없다. 다만 교사 경로 상관을 이용하는지는 따로 시험해야 한다. |
| A 의뢰에서 B 의뢰로 목표를 추론했는가 | 이 probe로는 모른다. B 방향 `gB`를 평가자가 직접 준다. |
| 자율 계획·상상이 되는가 | 이 probe로는 모른다. 이동 중 관측을 실제 `env_step`에서 받는다. 쓰기를 멈춘 기억 내용 검사다. |
| 느린 보상 머리가 가치 전환을 배웠는가 | 아니다. EL의 보상 머리는 최적화 대상에 없고 출력은 초기값 0이다. 현 `slot_B` 결과에는 영향이 없다. |
| 더 큰 기억·공동 공분산이 필요한가 | 그런 증거가 없다. 먼저 주소·시간·최신성 문제를 분리해야 한다. |

## 3. 고칠 순서와 단일 권고

평가 교정은 어떤 설계에도 먼저 적용한다. C 도착 직후를 기준으로 한다. 잔차 점수와 전체 예측 점수를 함께 기록한다. 빈칸을 포함한 template 우도와 출력 크기도 본다. 작은 벡터의 cosine만으로 예측 확신을 판단하지 않는다.

**제품 사실 분기에 한해, 사건으로 정렬한 KV + 고정 가소성 delta를 권고한다.** 먼저 고정 키로 검증한다. 학습으로 대체 가능한 게이트·표현은 그다음 느리게 학습한다. 채집처 ID, b0/b1 역할, 실제 산출물 배정은 모델 입력으로 주지 않는다.

| 구성 | 가장 작은 형태 | 겨냥하는 실패 | 빼면 무엇이 무너지는가 |
|---|---|---|---|
| 사실 주소 q | 시작 시 관측한 장소·행동의 정규화 키. 제품 사실 주소에는 카드·도장을 넣지 않는다. | 척도 자유도, 의뢰에 따른 주소 불일치 | 같은 장소를 다른 의뢰에서 읽을 때 주소가 달라질 수 있다. 정규화만으로 주소 분리가 보장되지는 않는다. |
| 원인 흔적 | 작업 시작 때 q를 보존한다. 완료까지 유지하고 나이만 갱신한다. | 이동 키가 원인 키를 덮는 지연 귀속 | 도착 오차가 출발지 대신 귀환 경로에 쓰인다. 이 환경은 pending 하나라 흔적 하나면 충분하다. |
| 사건·내용 분해 | 도착 여부/시각은 일반 동역학으로, 도착한 제품 내용은 `Mq`로 예측한다. 내용 쓰기는 도착 관측에서 한다. | 매 스텝 blank가 제품 연결을 반복 회귀하는 문제 | 도착하지 않은 시간과 제품 정체를 같은 회귀로 다시 섞는다. |
| 최신 사실 쓰기 | 아래 정밀도 가중 delta. gain을 과거 관측 횟수에 따라 영구히 줄이지 않는다. | 정적 RLS의 과거 평균화 | 여러 번 확인한 주소일수록 이후 변경이 잘 반영되지 않는다. |
| 느린 표현·동역학 | 장면 표현, 시작/도착 게이트, 지연·이동 규칙, 공통 decoder만 세계 간 학습한다. | 새로운 세계에 재사용할 구조 확보 | 이 축소판의 고정 특징 검사는 가능해도 일반 시각 세계로의 확장은 제한된다. |

이것은 이벤트 표를 무한히 보관하는 메모리가 아니다. 고정 행렬 M과 고정 차원 흔적이다. 이동 중에는 q를 읽기 위해 유지한다. 다른 사건을 전부 저장하지 않는다. 작업이 겹치는 세계로 넓힐 때만 고정 개수의 흔적이 필요한지 다시 검토한다.

시작은 관측된 채집처와 실행 행동으로, 완료는 관측된 HUD 변화로 식별할 수 있다. 진단 대조에서는 이 관측 규칙을 쓴다. 일반 에이전트에서는 같은 역할의 게이트와 시간 규칙을 느리게 배운다. 새 세계의 생산 배정은 반드시 세션의 M에만 쓴다.

### F와 쓰기 규칙

관측 우도를 `p(도착 여부 | 시간 상태) × p(제품 특징 | 도착, q, M)`로 나눈다. 미도착일 때 제품 내용 M은 해당 내용 우도에 등장하지 않는다. 따라서 미도착의 내용 쓰기가 0인 것은 이 모형에서의 경사다. 전체 HUD 우도를 그대로 두고 편의상 오차를 버리는 게이트와 구분한다.

도착한 내용 특징을 y, 갱신 전 예측을 `ŷ=M_old q`, 오차를 `δ_old=y−M_old q`라 하자. 필요하면 공통 내용 평균만 뺀다. 기존처럼 전체 시간 혼합의 WM 잔차와 원래 제품 template를 섞어 채점하지 않는다.

가장 작은 국소 목적은 다음과 같다. F의 가우시안 정확도 항과 고정 폭 변화 사전을 쓰는 MAP 근사다. 완전한 변분 필터라고 부르지 않는다.

```text
F_event(M) = π/2 · ||y − Mq||² − H/2 · log π
             + 1/(2η) · ||M − M_old||²_F

M_new = M_old + [ηπ / (1 + ηπ ||q||²)] · δ_old qᵀ
```

π는 **도착 내용 관측의 신뢰도**다. 과제의 출력이 결정적이면 우선 고정값이면 된다. 제품 정체를 아직 모르는 불확실성과 센서 잡음을 혼동하지 않는다. `ηπ`가 크고 q가 단위 벡터면 관측 방향을 최신 내용에 가깝게 교체한다. 작은 값은 잡음에 대한 완충이다. 비직교 주소 사이의 교차쓰기는 남는다. 이는 따로 측정한다.

이 규칙은 정밀도 가중 예측 오차의 KV 외적이다. 매 사건 같은 폭의 변화 사전을 쓰므로 오래 봤다는 이유로 가소성이 0으로 가지 않는다. 변화가 드문 잡음 환경에서 최적이라는 주장은 아니다. 현재 결정적 변경 과제의 첫 기준선이다.

현재 EP의 P만 `12×128²=196,608`개 스칼라다. 제품 분기의 M은 `8×128=1,024`개와 흔적 하나면 된다. 내용 쓰기는 `O(H·DK)`다. 상태·가중치 공동 공분산, 위험률 추정, 변화 가설 여러 개가 필요하지 않다.

정규화만으로 성능이 회복되면 더 많은 장치를 넣지 않는다. 도착 때만 쓰는 기존 누적 흔적이 원인 보존과 같은 성능이면 별도 snapshot도 생략할 수 있다. 반대로 큰 모델이 원인 게이트를 배울 수 있다는 가능성만으로 현재 귀속을 맞다고 간주하지도 않는다.

실제 비공개 의뢰 선택에는 별도의 빠른 목표 신념이 필요하다. 도착 정체와 보상으로 현재 의뢰를 추론해야 한다. 이를 느린 보상 머리에 외우게 하지 않는다. 현재 probe는 B를 외부에서 주므로 이 부분의 성공 여부는 이번 사실 기억 진단과 분리한다.

## 4. 진단을 가를 짧은 실험

**아래는 제안이며 실행하지 않았다.** 각 실험은 16–32세계, 1–5분을 목표로 한다. 첫 JIT 컴파일 시간은 별도다. 재학습은 포함하지 않는다. 현재 실행기는 p·vmax를 저장하지 않고 JSON만 저장한다. 보관된 체크포인트가 없다면 학습 키·WM을 쓰는 실험을 몇 분 안에 재현할 수 있다고 약속할 수 없다. 그런 행은 체크포인트가 있을 때만 한다. 나머지는 고정 난수 키·WM 없음으로 인과를 먼저 가른다.

공통 기록은 세계별 승패, b1−b0 점수차, 출력 크기, 제품 A/B/C와 blank 오차, 정확 동점 수다. 최종 비율만 남기지 않는다. 같은 세계를 짝지어 비교한다.

| 우선순위·실험 | 고정·변경 | 예측과 판별 |
|---|---|---|
| 1. 시점과 보존 쓰기 | 동일 세션에서 C 직후 / 원래 끝 / padded 끝을 비교한다. 별도로 보존 256스텝의 M·P 쓰기만 멈춘다. e는 진행한다. | 뒤로 갈수록 악화하거나 동결 시 회복하면 blank·경로 쓰기 간섭이다. C 직후부터 같게 실패하면 padding만으로 설명할 수 없다. 고정 키로 가능하다. |
| 2. 주소의 문맥 불변성 | 고정 키의 입력에서만 HUD를 상수로 마스킹한다. 내용 target은 유지한다. b1 최초 기록과 최종 읽기 주소의 cosine도 잰다. 보관 모델이 있으면 학습 키의 단위 정규화만 적용한 판도 별도 비교한다. | HUD 제거로 b1 유사도·성공률이 오르면 문맥 의존 가설을 지지한다. 정규화만 효과가 나면 척도부터 고친다. 둘 다 변화가 작으면 우선순위를 내린다. |
| 3. 지연 귀속 | 내용 쓰기를 도착으로 맞춘 뒤, 모든 스텝 누적 e / 상호작용 키만 넣은 e / 시작 키 snapshot을 비교한다. 같은 키·쓰기 규칙을 쓴다. | 뒤 두 판만 좋아지면 원인 혼합이다. 상호작용 흔적과 snapshot이 같으면 더 작은 흔적 규칙을 택한다. 모두 같으면 주소 분리·갱신을 본다. |
| 4. 최신성 × 귀속 | 같은 내용 관측에서 누적 e / 시작 q와 RLS / 고정 gain delta의 2×2를 비교한다. C 전후 b0의 B·C 예측과 gain을 잰다. | q만 효과면 귀속이 우선이다. delta만 효과면 과거 평균화가 우선이다. 둘을 함께 써야 오르면 두 문제가 결합했다. 고정 키로 가능하다. |
| 5. 주소 자체의 상한 | 진단에만 실제 사이트 one-hot을 써서 동일 사건 쓰기·읽기를 한다. 관측 키와 비교한다. | one-hot도 실패하면 읽기·시점·갱신부터 의심한다. one-hot만 성공하면 주소 표현·충돌 문제다. 해결책에는 사이트 ID를 주입하지 않는다. |
| 6. 읽기·분산 감사 | 체크포인트가 있으면 같은 기억의 `Mz` / `μ⁰+Mz` / A·B·C·blank template 우도를 비교한다. 도착/미도착별 `‖err‖²/(H·S)`도 잰다. | 순위만 바뀌면 측정 정의의 영향이다. 표준화 오차가 지속해서 1과 크게 다르면 분산 보정을 먼저 한다. 키 크기만으로 원인을 설명하지 않는다. |
| 7. 검출기 단독 검사 | 고정된 정확 원인 주소에서만 첫 변화 χ와 gain을 잰다. 같은 코드로 ‘변경 없음’도 돌린다. WM 없는 판은 관측된 도착 내용의 분산을 변경 prior로 쓴다. | 정확 주소에서도 χ가 안 뜨면 prior·위험률 척도 문제다. 정확 주소에서는 내용까지 갱신되는데 현재 흔적에서만 실패하면 귀속 가설을 지지한다. χ만 뜨고 내용 갱신이 안 되면 gain·읽기도 본다. |
| 8. 느린 표현의 역할 | 체크포인트가 있으면 새 세계의 생산 배정만 다시 섞고, 제품 사실 M 쓰기 켬/끔을 비교한다. 도장·보상 입력도 차단한다. | 쓰기 켬만 새 배정을 따라야 한다. 쓰기 없이 우연 수준을 넘어 체계적으로 새 배정을 맞히면 평가 경로·관측 누출부터 확인한다. 배정 변경에 과도하게 취약하면 교사 상관 의존을 의심한다. |

최초 관찰 뒤, A×4 뒤, B 보상 뒤, 보존 뒤, C 직후의 b1 읽기도 함께 남긴다. C 전부터 b1이 약하다면 C 변경을 놓친 것만으로는 설명할 수 없다. 망각을 켠 판에서는 이전 오탐도 확인한다.

**진행 기준:** 1–4에서 측정 정의와 귀속을 먼저 가른다. 권고한 작은 사실 시냅스가 b1을 보존하며 b0를 C로 갱신하는지 확인한다. 그 뒤에만 같은 규칙으로 키를 느리게 학습한다. 작은 기준선의 주소·읽기·갱신을 확인한 뒤에도 남는 실패가 있을 때만 더 무거운 장치를 검토한다.
