## 1. 지금까지 확정된 것 (2026-11-14~15 세션)

- **목표**: 마인크래프트 (DreamerV3 다이아몬드 설정, 세션 최대 36,000스텝)에서 실시간으로 적응하는 에이전트. 추상화하면 "끝없이 변하는 흐름에서 고정된 기억 크기와 스텝당 고정 계산으로, 저장한 것의 미래 쓸모를 최대로". 추론 중 경사 갱신 없음.
- **R1 → R3 결정 (사용자)**: MQAR (R1)에서 성공한 형태는 Craftax 형태로 그대로 옮길 수 없었다. 그래서 Craftax와 같은 꼴의 입력 (타일 패치 + 행동 + 보상)인 forage 월드에서 설계한다. 여기서 성공하면 R4 (Craftax)에서 달라지는 것은 난이도와 학습 규모뿐이어야 한다. **설계의 판정 기준은 "Craftax로 그대로 옮길 수 있는 형태인가"다.**
- **tdp가 실패한 이유 (추상화)**: 보상 기억에 반드시 필요한 성질 셋이 없었다. (1) 키 = 결정 시점 정보로 만든 (상황 × 행동), 결과는 값에만. (2) 공은 결과보다 먼저 온 것에만 (방향성, 짧은 창). (3) 공 배정 창과 보존 시간 분리, 공 받은 것만 놀라움으로 게이트해 남김.
- **tdpc (세 성질을 넣은 수정)**: 학습 전부터 22점, 무너지지 않음. 그러나 그 장기 기억은 **선형 TD(λ)** 그 자체다 (빠른 가중치 w를 에피소드마다 비움, 키는 느린 가중치가 학습). 이것은 알려진 것이고 (Mountain Car 타일 코딩 제어와 같은 쓰기 식, w의 수명과 특징의 출처만 다름; 에피소드 제어 NEC 계열), **기여가 아니라 정상 동작 확인**이다. 학습 전 synapse가 30점인 것도 같은 이유 (시야가 위치마다 거의 유일 = 구별되는 특징 + TD(λ)).
- **TD(λ)가 원리적으로 못 하는 것**: TD는 지금 목표에 대한 가치를 캐시한다. 보상이 오기 전에는 아무것도 쓰지 않는다 (tdpc도 첫 보상 전 δ = 0, w = 0). 쓸 것을 고르지 않고, 버릴 것을 정하지 않는다.
- **갈리는 지점 (이 연구가 기여해야 할 곳)**: "보상이 오기 전에 본 것을, 나중에 그것이 필요해졌을 때 꺼내 쓰는가" (마인크래프트: 돌 곡괭이 전에 본 철광석 위치). 그리고 그것을 고정 크기 기억으로, 학습 조각 길이보다 훨씬 먼 과거에서, 중요한 것만 골라 써서, 증거로만 버리며 하는가.
- **사용자의 입장**: DreamerV3의 GRU는 kNN·큰 기억 없이 고정 크기로 충분하다 (GRU는 상태 추정을 맡고 세계·보상 지식은 느린 가중치가 가진다). 기억은 **흔적이어도 된다**고 본다. 실마리는 **능동적 추론·자유에너지원리** 관점에서 자연스럽게 형식화될 것이고 (기억 = 생성 모델의 빠른 파라미터, 쓰기 = 정밀도 가중 믿음 갱신, 관련성 = 기대 자유에너지의 실용·인식 가치, 망각 = 변동성), **BTSP**를 함께 보면 좋겠다 (플래토가 언제 쓸지, BTSP가 무엇을 어떻게 한 번에 덮어쓸지).
- 이전 BTSP 노선이 "DQN 변형을 넘는 기여 없음"으로 닫힌 이유: BTSP를 Q값 출력층으로 써서 결국 가치 캐시 (TD)와 같은 일을 시켰기 때문이다.

## 2. 해 줄 것

### 2.1 문제 정의
- 무엇이 주어지고 (관측, 행동, 보상, 기억 크기·계산 제약), 무엇을 최적화하며, 기억이 내려야 하는 결정 (쓰기, 유지·망각, 읽기)이 각각 무엇인지 식으로 적는다.
- TD(λ) / 에피소드 제어 (NEC) / DreamerV3의 GRU가 이 정의에서 **어디까지 하고 어디서 원리적으로 못 하는지**를 분명히 가른다. "새로운 것"이 정확히 무엇인지 한 문장으로 말할 수 있어야 한다.
- 반증 가능한 형태로: 이 문제를 풀었다고 말하려면 어떤 측정에서 무엇이 보여야 하는가.

### 2.2 아키텍처 설계
- 구성 요소, 식, 느린 가중치 (역전파로 배움)와 빠른 상태 (순전파 안에서 갱신)의 분업, 쓰기·망각·읽기 각각의 결정 기준, 행동 선택.
- 자유에너지원리에서 각 결정의 기준이 **유도되어야** 한다 (손으로 문턱·손실·머리를 덧붙이지 않는다; ROADMAP 1절 원칙 5). 자유 파라미터는 원리로 정하거나 실험 전에 고정한다.
- BTSP를 쓴다면 무엇을 무엇에 대응시키는지 (ET, IS, 플래토, 가중치 의존 방향)와, 그것이 자유에너지원리의 어떤 양에서 나오는지.
- 흔적 (TDP의 복소 대역 흔적 포함)으로 무엇을 할 수 있고 무엇은 할 수 없는지. 쓴다면 band_product의 "보존과 창이 한 극점에 묶임"을 어떻게 다루는지.
- 고정 기억 크기·스텝당 고정 계산을 지키는지, Craftax (관측 63×63 타일 패치 81개, 행동 17개)와 이후 DreamerV3 RSSM 결정론 경로에 **그대로** 옮겨지는지 확인한다. 옮길 때 바뀌는 것이 난이도와 규모 외에 있다면 명시한다.
- 가장 단순한 대안과 비교해 각 구성 요소가 왜 필요한지 (빼면 무엇이 무너지는지).

### 2.3 첫 입증 과제와 사전 예측
- forage 월드의 손잡이로 만들 수 있는, 2.1의 "새로운 것"만 정확히 재는 최소 과제 (예: 보상이 처음엔 꺼져 있다 나중에 켜짐, 보이는 표식과 늦은 필요).
- 비교군: 가장 단순한 것과 가장 강한 것 둘 다 (tdpc = TD(λ), GRU, 정답 상한 등).
- 사전 예측 표와 실패 기준 (실행 전에 고정할 수 있는 형태로).

### 2.4 선행 연구
- 이 형식화와 겹치는 선행 연구를 찾고, 원문을 확인한 것과 기억에 의존한 것을 표기한다 ([확인] / [기억]). 겹친다면 무엇이 다른지.

## 3. 작업 규칙

- 결과는 **`docs/world/architecture_design.md`** 한 파일에 쓴다. 저장소 문서의 문체 (한국어, 짧은 문장, 표, 근거 표기 [표준]/[확인]/[기억]/[유도]/[가설])를 따른다.

- 끝나면 `docs/world/architecture_design.md`를 git에 커밋한다 (작성자 Codex, 메시지 영어). 푸시는 인증이 없어 안 되니 시도하지 않는다.
- 마지막 응답에는 문서의 요약 (문제 정의 한 문단, 아키텍처 핵심, 첫 입증 과제, 열린 질문)을 적는다.
