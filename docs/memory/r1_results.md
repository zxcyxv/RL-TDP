# R1 결과: 키별 신뢰도 추정과 변화·잡음의 구별

실행: 2026-11-14, 시드 1개. 사전 예측: [`r1_predictions.md`](r1_predictions.md). 재현: `./scripts/memory/r1.sh`, 표: `python -m rltdp.memory.report`.

## 0. 한눈에

- 값이 바뀌지 않는 흐름 (B)에서는 모든 모델이 베이즈 상한에 붙는다. 키별 신뢰도 추정은 이득이 없다.
- 값이 단서 없이 바뀌는 흐름 (C)에서만 갈린다. 토큰만 보는 게이트 (gdn, kdn)는 깨끗한 키와 오염되는 키를 구별하지 못해
  모든 키에 "두 번 봐야 바꾼다"를 적용한다. 키별로 잡음을 추정하는 ours는 깨끗한 키를 한 번에 바꾼다.
- 게이트가 쓰기 직전의 읽기와 오차를 보면 (gdn_read, kdn_read) 전체 정확도는 ours와 같아진다. 변화 직후의 반응은 여전히 ours가 빠르다.
- 따라서 "키별 신뢰도를 추정해 쓰기 세기를 정한다"는 동작은 원리로 정한 형태와 학습된 게이트가 모두 도달하는 해다.
  ours는 그것을 게이트 학습 없이 스칼라 6개로 낸다.

## 1. 실행 설정 (사전 예측 문서와 달라진 것)

- 배치 128 × 3,000반복 → 배치 512 × 1,500반복 (A는 배치 128 × 600반복). 파이썬 루프 오버헤드 때문에 배치를 키우는 쪽이 싸다. B·C를 돌리기 전에 바꿨다.
- 반복 = 가중치 갱신 한 번. 매번 새 흐름을 생성하므로 에폭은 없다.

## 4. 읽기

- B의 gdn 예측이 틀린 이유: 값을 맞히려면 평균에서 참값이 최다이기만 하면 된다. 고정 비율 평균으로 충분하다.
- 신뢰도 추정은 변화가 있을 때만 쓸모가 있다. 쓰기 (R1)와 유지·망각 (R2)은 따로 시험되지 않는다.
- ours의 약점은 흐름 초반이다. 깨끗한 키인지 알려면 여러 번 봐야 한다 (잡음 추정이 고정 비율 이동 평균, 사전은 "잡음").
  길이 256에서 변화 직후 정확도가 0.829인 이유다.
- 학습된 ν가 0.87~2.9다. 값이 64차원이므로 가우시안 가정이 맞다면 수십이어야 한다. 실제 잡음은 "맞거나 완전히 틀리거나"의 혼합이다.
